# Deploying the landing page live

**Read this before you try to deploy; it saves hours.** The production landing page is often not
your static HTML prototype but a **Next.js repo** (the client's site, or a repo built from the
design). Your static build is then the design and copy spec; deploy the repo and port your copy into
its components.

## Before you edit the repo
- Read its README and any contributor notes, and check the framework version before editing code;
  conventions change between major versions.
- Some design-to-code exports produce pixel-positioned components. Change copy, not geometry.
- `app/layout.tsx` holds the `metadata` export (title and description). A fresh scaffold defaults it
  to "Create Next App" / "Generated by create next app". Fix this (below).
- If the repo is owned by an account other than the one your hosting is linked to, plan to fork it
  (below).

## Why you probably can't deploy from the sandbox
- Sandbox networks are often allowlisted: PyPI works; the npm registry, GitHub writes, the Vercel API
  and font CDNs usually don't. The Vercel CLI fails without npm, and direct API calls time out.
- A hosting connector's "deploy" call made without files may only return CLI instructions, not a
  deployment. Some accept a file tree, but that's meant for files without a repo and is impractical
  for a full Next.js app.
- So for a repo already on GitHub, the path is the **Vercel ↔ GitHub git integration**, driven
  through the Vercel connector's create-project-from-repo call (or the dashboard). Linking a repo
  **does not deploy it**: a push to the linked repository does.

## The authorisation sequence (each error tells you the next fix)
You can't authenticate yourself from a non-interactive session. The user authorises through their
connector settings and the Vercel/GitHub UI. Expect this sequence of errors when you try to create
the project from the repo:
1. **403 "You don't have permission to create the project."** The Vercel connector is read-only
   scoped. The user reconnects Vercel with write access.
2. **403 asking to re-authenticate to a team's projects scope.** The reconnect defaulted to the
   personal scope. The user reconnects and grants the specific team's scope.
3. **400 "add a Login Connection to your GitHub account first."** The Vercel account has no GitHub
   login linked. The user: Vercel Settings → Login Connections → Connect GitHub.
4. **400 "install the GitHub integration first."** The Vercel GitHub App isn't installed on the
   repo owner's account. Install it with access to the repo.

## The account-mismatch trap and the clean unblocker
Three identities are in play and they often differ: who owns the hosting account, which GitHub user
that hosting account signs in with, and who owns the repository. The hosting side can import only
repositories that its GitHub identity has access to, and granting access across owners is slow and
error-prone. **The clean fix is a fork:** in the user's browser, open the repository, choose Fork,
set the owner to the GitHub user the hosting account signs in with, and create the fork. Creating
the project from `<that-user>/<repo>` then works.

## Trigger the first deploy (linking doesn't)
After linking, no deployment exists; a push creates one. If you can't push from the sandbox, make a
trivial commit in the GitHub web editor: open `README.md` on the default branch, add a line, and
commit directly to that branch. The push triggers Vercel, and a production deploy of a small
Next.js site is typically ready in about a minute. Every later push auto-deploys; pull requests get
preview URLs.

## Verify in the browser
The connector may not be allowed to list deployments even after the scope fix (permissions are
granular). So verify in the browser: open the Vercel project dashboard, check that the production
deployment is Ready and note its domain. Then open the live URL and confirm it renders and the
browser tab `<title>` is correct.

## Fix the title and meta description (app/layout.tsx)
Replace the default title. Editing `app/layout.tsx` in the GitHub web editor works; watch for:
- Selecting a whole line by triple-click can include its trailing newline, so typing a replacement
  merges the next line up. It usually stays valid code but looks wrong; reformat later.
- Long lines scroll horizontally with wrapping off: zoom or screenshot to check the edit before
  committing.
- A bad commit can't take the site down: Vercel only promotes successful builds, so the last good
  deploy keeps serving while you fix a broken one. That makes the edit low-risk.

Set a proper `title` and `description` (and optionally Open Graph tags), commit to the default branch
(which redeploys), and confirm the tab title updates on the live URL.

## Wiring after go-live
Propagate the live landing URL into the master sheet's `landing_url`, every sequence email and the ad
destinations. Rebuild and re-package the sequence and ad packs. The pipeline through the landing page
is then complete; what remains (the LinkedIn upload, the cold-email and CRM loads) is manual by
platform limit.
