# Long-form deck: required analyses

The long deck is the full argument; the condensed deck is a cut of it, not a different story. If a
reference deck exists, its slide list and order win. Otherwise use this as a checklist: every analysis
below must appear, and you order the modules to tell this client's story. The default grouping follows the
skill's priority (audience and demand first, technical last, because content leads the roadmap). Write
each slide title as its finding, not as the label used here.

## Opening

- [ ] Cover, and a short "how to read this deck" with the three files that ship alongside it
- [ ] Executive summary: the readiness index and its five dimensions (`scorecard.md`), the top owned
      priority, and the three biggest gaps
- [ ] Optional, one slide at most: why answer engines matter for this category now (sourced stats)

## Module A: the buyer (`audience-research.md`)

- [ ] How the audience data is gathered
- [ ] Who the buyers are (demographics with segment reads) and how they compare with the personas
- [ ] Where they spend attention: social platforms vs average, sites, channels, podcasts, communities
- [ ] Which search and AI engines they use vs average, and the engines the scorecard will track

## Module B: demand and the competitive field (`competitor-pareto-analysis.md`)

- [ ] The tiered competitor map (peer cohort vs adjacent incumbents)
- [ ] Brand vs non-brand share per competitor, and the exception as a case study
- [ ] The vital-few pages table, then the all-competitor page economics
- [ ] AI-citation coverage per competitor (prompts per ranking page)

## Module C: AI answers today (`ai-visibility-baseline.md`)

- [ ] How the prompt set was built (real queries, gap themes, funnel mix)
- [ ] Share-of-voice scoreboard across the non-branded set, led by where the client loses
- [ ] Prompt-level wins and losses, including the trust cluster and open goals split by KPI
- [ ] Accuracy check: what the engines get wrong about the client
- [ ] Owned vs earned message alignment

## Module D: where the answers come from (`citation-sources-and-offsite.md`)

- [ ] Sources by type with retrieved % and cite rate
- [ ] The highest-leverage earned channels, verified live
- [ ] Review-site presence and the backlink profile
- [ ] Expertise and trust signals (authors, credentials, proof) on the site and off it

## Module E: content and topics (`slide-execution-depth.md`, `what-wins-content.md`)

- [ ] Topical authority map: the theme table, then the demand vs AI-presence chart
- [ ] Answer-first coverage on the top 25 pages, with example rewrites
- [ ] Formatting and extractability on the priority pages
- [ ] Information gain and the top proprietary data opportunities
- [ ] What wins: page-type economics, the winning-page skeleton, glossary and hub strategy
- [ ] Content velocity vs competitors (only with real dates)

## Module F: site structure

- [ ] Navigation audit vs competitors, with the recommended menu
- [ ] Internal linking: the hub model and the link rules

## Module G: technical foundation (`technical-aeo-audit.md`)

- [ ] Crawl and indexation, including AI crawler access and the robots.txt / llms.txt read
- [ ] Structured data: what is present (raw HTML), what to add, in order
- [ ] Entity presence (knowledge panel, Wikidata, consistent profiles)
- [ ] Speed (field data first) and on-page priorities, High / Medium / Low

## Close: the way forward (content first)

- [ ] Prioritized recommendations and quick wins
- [ ] What to publish (from the Content Plan sheet) and the content calendar
- [ ] The 90-day plan with the content track first
- [ ] How progress is measured (index re-score, visibility and share of voice, content shipped)
- [ ] The experiment backlog
- [ ] Deliverables and phases, then Q&A
